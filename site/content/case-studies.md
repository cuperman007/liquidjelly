## 1. Connecting pharmacy reporting to NHS systems

**Organisation:** PHOENIX Medical Supplies  
**Project:** Patient Safety NHS Integration  
**Dates:** January 2023 – March 2024  
**Role:** Contract full-stack developer

### The requirement

An existing patient safety application needed to communicate with an NHS FHIR API. The project required both a way to collect questionnaire responses and a way to map that information into the structures defined by the receiving system.

### Our contribution

We updated the application’s integration and created a dynamic, configurable questionnaire system. We implemented output mapping against the requirements described in NHS FHIR server capability documents, using ASP.NET Core, Blazor and Azure services.

### What was delivered

A configurable questionnaire capability and the application changes needed to communicate with the NHS FHIR interface. The work brought together user-facing forms, structured data and an external healthcare integration.

### Why this experience matters

Connecting new capabilities to established systems requires careful handling of data structures and interface requirements. This project provides a concrete example of that integration work.

**Homepage excerpt:** Configurable questionnaires and structured FHIR output, connecting an existing pharmacy application with NHS systems.

**Suggested visual:** A simple questionnaire → field mapping → FHIR interface diagram. Use illustrative field names, with no patient data.

**Source:** CV page 1, “Patient Safety NHS Integration”. No clinical outcomes, formal compliance certification or measured time savings are asserted.

## 2. Giving a development team a common foundation

**Organisation:** PHOENIX Medical Supplies  
**Project:** .NET Core Application Framework  
**Dates:** March – September 2020  
**Role:** Contract developer; framework design and team transition

### The requirement

Legacy intranet systems needed a framework for migration to a modern application stack. The development team also needed support adopting the tools and practices that would underpin the new approach.

### Our contribution

We designed and implemented an application framework using .NET Core, Blazor and Azure. Alongside the technical work, we organised the team’s transition and training in .NET, Git, unit testing and Blazor.

A common application framework and a supported transition to the associated development practices. The work addressed both the software foundation and the team’s ability to use it.

### Why this experience matters

Introducing a new tool changes how a team works. This experience is relevant to helping teams adopt AI-assisted development through practical training, review and consistent engineering practices.

**Homepage excerpt:** A shared .NET and Blazor framework, backed by hands-on support for the team adopting it.

**Suggested visual:** An architectural overview with separate labels for the application framework, source control, automated tests and deployment.

## 6. Designing a tracking portal for reuse

**Dates:** June – July 2016  
**Role:** Sole developer
